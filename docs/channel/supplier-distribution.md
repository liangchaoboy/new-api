# 供应渠道分发实施计划

## 目标与边界

### 当前目标：A 客户、B 转售商、C 供应商

B 是唯一的转售商，A1、A2、A3 分别是下游客户，C1、C2、C3 分别是上游供应商。B 给每个 C 提供独立的普通上号账号。C 在 B 的站点录入自己的渠道，B 按单条渠道选择 A。同一个 C 的不同渠道可以分配给不同 A。

B 保存 A 的实例地址、账号名和加密的登录密码，使用 A 实际授予该账号的 API 或网页工作台权限完成录入。一次完整交付须能记录 A 返回的渠道或供货记录 ID，并能通过该 ID 回读。B 采集 A 提供的渠道用量，B 可以查看全部，C 只可查看归属自己渠道的数据。若 A 的页面只展示账号合计且同一账号承载多个 C 的渠道，则该合计无法作为任一 C 的渠道用量。

标准发行版的普通用户权限仅包括本人令牌及个人消费等操作。浏览器和后台 API 共享该权限边界。有供货工作台的站点应以实际表单、稳定远端标识和报表字段作为对接依据。下面保留的手工直供和专用接收端属于此前方案，其验收记录单独保留。

### 当前模式的操作与验收

| 谁操作 | 操作 | 可核对的结果 |
| --- | --- | --- |
| A → B | A 提供其独占实例的站点地址（也可填写 `/sign-in`）、用户名和密码。B 在「供应渠道 → 下游实例」登记。 | B 验证本人身份及渠道、日志接口。管理账号需能查看、写入、修改敏感渠道字段及停用渠道，读取消费日志需要相应日志权限。 |
| B → C | B 在「用户管理」为每位 C 创建独立普通账号。C 在 B 的「供应渠道」添加名称、类型、原始上游地址、模型和密钥。 | 供应商账号只能维护和查询自己的资源。普通登录账号可提交待分配资源；由 B 决定哪些资源可以交付。 |
| B → A1 | B 选择一条资源，点击「分配渠道」，选择客户和客户实例上的分组。 | B 调用 A 的渠道管理接口创建记录，按分配标记回读渠道 ID 和配置版本。推理从 A 直达 C，A 的分组决定其内部哪些用户可以使用。 |
| C 更新或 B 改派 | C 更新配置时，B 在 A 的原渠道 ID 上修改。B 从 A1 改派至 A2 时，先替换 A1 渠道的密钥、停用并回读确认，再在 A2 创建渠道。 | B 在任何时刻最多维持一个生效的客户分配。撤回限于 B 管理的远端渠道，已经离开该渠道的密钥副本须在上游轮换。 |
| B / C 查看 | 打开具体渠道的「用量」和「操作日志」。 | B 可查询所有供应渠道，C 仅可查询自己的渠道。按客户、远端渠道 ID、UTC 日归集消费记录、输入输出 Token 及 A 日志中的原始额度。改派前后的历史分别归原客户。 |

下游客户的名称、地址、登录名、分组及远端渠道 ID 仅向同时拥有渠道读取和敏感写入权限的 B 管理员展示。渠道分配另需渠道写入权限。供应商可以查看渠道是否已生效、操作日志和用量，以渠道总量为准。服务端也校验下游名单和按客户筛选的用量接口。授权规则参考 OWASP ASVS 5.0.0 和 OWASP Authorization Cheat Sheet，回归测试覆盖具有普通渠道读写权限的管理员和普通供应商。[OWASP ASVS 5.0.0](https://asvs.owasp.org/) · [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

B 的「数据看板」和「使用日志」各有「供应渠道用量」页签，按登录账号读取其供应渠道的同步快照。看板汇总请求和 Token，并按选定 UTC 日期范围计算分钟平均值。今天只计算到已同步的时间。日志按 UTC 日期、供应渠道和模型展示用量。缓存读取和写入使用 A 返回的字段。缺少该字段时显示无数据，收到 0 时按 0 展示。额度按下游记录原值显示在明细中。数据随后台同步更新。

客户实例使用 HTTPS。仅本机回环测试允许 HTTP。B 使用持续配置的 `CRYPTO_SECRET`（或项目支持的持久 `SESSION_SECRET`）加密 A 的密码；业务接口不返回密码或认证会话。修改密码后，在同一目标上重新验证同一账号即可。遇到交互式验证时由 A 提供受支持的登录方式。兼容旧手工模式的客户地址，可在全部分配撤回后重新登记凭据。管理员应在客户实例上为 B 保留分配标记及查看渠道的权限。

B 优先探测部分供货工作台提供的 `/api/data/channel_daily`，按日志来源、UTC 日和渠道 ID 采集；该接口只提供渠道汇总。标准 new-api 使用 `/api/log/` 的消费类型、渠道和时间过滤，校验每条日志再按模型分组。数据前提是 A 开启并保留消费日志。远端拒绝访问、分页不一致、已有计数回退均保留已有快照并标为不完整。渠道创建结果不明时，B 按持久化的分配标记查询并确认已有记录。一直查不到、原标记被改动或撤回无法确认时，管理员可在 A 的渠道管理和审计记录中核对；B 会等待确认后再交付下一家。

本仓库的 `e2e/supplier_customer.py` 可复现标准版联调。它启动一个 B 和两个标准 A，B 创建两个普通供应商账号，使用本地模型服务产生消费，验证 C1 在 A1 的 10 条、在 A2 的 6 条，C2 的独立消费，以及归档后的历史与权限。运行方式：

```sh
go build -o /tmp/new-api-reseller .
python3 e2e/supplier_customer.py /tmp/new-api-reseller /path/to/stock-new-api
```

### 既有手工直供模式：客户自管的标准 new-api

每个下游客户独占一套标准 new-api，渠道交付对象由客户实例的访问地址标识。中心在该业务中承担上游供应商角色。下游提供的普通账号可以登录该站点、管理自己的调用令牌和读取本账号的消费记录。站点渠道的新增、修改、停用以及全渠道日志读取属于下游管理员权限。

管理员在中心的「下游实例」填写站点根地址、普通用户名和密码。中心调用站点公开的登录接口，再通过本人资料接口验证登录身份，最后退出该次会话。中心保存实例地址及验证过的账号 ID，同一站点更换联络账号不会改变渠道绑定。密码和登录会话仅在此次验证时使用。要求验证码、二次验证或禁用密码登录的站点会明确提示无法仅凭账号密码验证。

| 阶段 | 中心与客户分别执行的操作 |
| --- | --- |
| 绑定 | 中心按单条渠道选择客户实例地址。每个客户独占实例，无需填写客户内部 UID，新渠道初始为待分配。 |
| 交付 | 中心 root 管理员使用已注册的 Passkey 或 2FA，按渠道、目标及版本完成一次性验证，再导出供应商的原始地址、模型和专用 Key，交给客户管理员。审计记录目标、操作者及版本。 |
| 使用 | 客户管理员在自己的标准 new-api 中录入渠道。客户用户请求经自己的实例直达供应商，中心无须转发推理流量。「接入信息已导出」只表示中心交付了凭据。 |
| 计量 | 对 New API 类型的供应端，读取专用 Key 的 `GET /api/usage/token/` 中的 `data.total_used`，显示该 Key 全生命周期的累计额度和采集时间。中心会定期采集并在查看时刷新，此指标不参与按日请求数、Token 或 UID 的汇总。其他上游、查询失败或无历史快照时，显示上次记录或用量不可用。 |
| 撤回、归档与改派 | 已导出的凭据需要供应商在原始上游禁用。供应商或有权限的中心管理员确认吊销后，中心关闭旧分配并保留审计和用量快照。改派需要一把新的专用 Key。尚未导出的分配可直接撤回。 |

同一供应商可以把 C1、C2 交给不同客户实例。地址按实例登记，每次导出都绑定到选定的客户。下游收到的是可直接调用上游的原始凭据，持有者可在中心之外使用；实际限制和吊销由上游提供方执行。中心不持有下游管理员权限，不保证客户已配置渠道，也不将普通账号的个人消费冒充客户实例的渠道用量。

### 已有分发接收端的兼容模式

供应商 A 提供渠道 C。管理员将 C 分配给目标 new-api 上的用户 B。B 使用已有的 API Key 向目标实例发送请求，目标实例使用 C 调用供应商。中心保存资源、分配、操作记录和用量汇总。每条资源同时最多有一个已生效的使用者，使用者由目标实例和该实例内的 UID 共同标识。

### 中心管理员按渠道固定下游

管理员在中心「供应渠道」找到供应商 A 名下的渠道 C，点击「分配渠道」，选择目标实例 T，输入该实例的用户 B 的 UID。收到 T 的回执后，C 固定供应给 **(T, B)**。分配持久保存，跨请求、网关重启、模型更新和密钥轮换继续生效，直到管理员改派或渠道被撤回、归档。界面分别显示期望目标与已生效目标，改派时须收到旧分配的撤回回执才能启用新分配。

管理员按渠道 ID 独立分配和改派。例如，同一供应商的 C1 可以固定给 B，C2 可以固定给 D，各自记录配置、用量和操作日志。新增渠道 C3 初始为待分配，由管理员单独指定下游。B 在目标实例仍可按既有路由使用其他有权使用的渠道。

| 角色 | 操作范围 |
| --- | --- |
| 供应商 | 创建、查看、修改、停用、删除自己的资源；查看各渠道的历史用量、同步结果和脱敏变更记录 |
| 管理员 | 管理目标实例；按用户分配、改派、撤回渠道；查看所有渠道用量并按时间、模型、使用者筛选 |
| 下游用户 | 通过目标实例使用获分配渠道；分配生效前、撤回确认后的新请求均不可命中该渠道 |

## 兼容接收端的实现顺序与数据约定

1. **目标端路由隔离。** 用两个同组账户、一条受管渠道及一条普通渠道覆盖普通选路、固定渠道、亲和、重试、缓存和数据库路径。使用认证中间件设置的 UID。既有渠道保持共享语义。受管渠道的使用者一经创建即固定，每次改派使用新的远端渠道 ID。这样迟到的消费日志和在途请求仍可通过旧渠道 ID 精确归属。
2. **目标端配置协议。** 中心提交分配 ID、单调递增的版本、UID 和允许下发的配置。目标端校验服务身份、操作范围、用户和配置，在同一事务内持久化受管渠道、路由能力和已应用版本。相同请求重放返回相同结果，过期版本不能复活已撤回的绑定。多节点部署对受管渠道在开始使用凭证前确认撤回状态。目标端不支持协议时明确报告能力缺失。
3. **中心资源与分配。** 资源归属从已登录的供应商账户推导；资源 ID 不代替归属校验。将期望状态、配置版本和待同步工作一起写入事务。每条资源按版本串行推进，保存历次分配。旧目标未确认撤回时保留“等待撤回”，新目标保持未启用。更新和删除失败可重试，已撤回资源归档后保留历史。
4. **用量与审计。** 复用目标端消费记录，按实例、远端渠道、模型和时间窗口聚合消费记录数、输入和输出 Token。中心对同一分配和窗口覆盖校正，支持迟到记录、补采和重新对账。目标端关闭消费日志或采集失败时显示数据可用状态和上次同步时间。报表查询在后端按供应商归属或管理员权限限定范围。操作日志记录操作者、分配、版本、确认结果和脱敏错误。密钥加密存放并通过 TLS 下发，密钥和原始请求体禁止进入审计日志。
5. **界面。** 供应商使用“我的供应渠道”维护配置和查询用量；管理员从资源详情选择实例及用户，可查看期望与实际版本、改派历史、重试同步和按使用者细分的报表。复用项目组件和七种界面语言。
6. **发布与回退。** 从功能分支构建。记录三种主库版本，覆盖 SQLite、MySQL、PostgreSQL 的新装、从已发布版本升级和两次启动，核对原有数据和约束。验证独立日志库和 ClickHouse 读取。目标机先并行运行隔离实例、独立数据卷和测试凭证，使用一条测试资源验收。切换服务前记录原构件和配置备份；回退时先撤回受管渠道并确认失效，再恢复旧版本，防止旧版本将受管渠道作为共享渠道调度。

## 既有模式的接入与操作

1. 使用兼容模式时，中心和目标实例使用此分支版本。目标实例的所有流量节点均需升级后再启用专属渠道。旧版本会忽略用户归属字段。中心配置持久的 `CRYPTO_SECRET` 或 `SESSION_SECRET` 并在各节点保持一致，至少一个中心主节点负责同步。备份数据库时同时保存加密密钥。
2. 在目标实例为专用管理账号授予「接收供应渠道」权限。在安全设置创建作用域为 `channel:receive_supply` 的个人访问令牌。资源下发和用量读取均按创建回执的目标账号隔离，令牌轮换沿用同一个账号。
3. 已有接收端目标可继续通过「供应渠道 → 下游实例」轮换管理令牌，原有 PAT 登记 API 继续支持。新建界面默认使用标准实例的地址和普通账号密码。创建和轮换目标凭据需要敏感渠道写权限。生产地址使用 HTTPS，独立本机联调支持回环 HTTP。创建和轮换前，中心通过接收端身份接口核验新 PAT 的权限及账号，轮换失败会保留旧凭据。升级时应先升级目标端。旧登记优先用已签发回执确认原账号，无历史回执时用仍有效的旧 PAT 确认身份。实例地址在创建后固定，以保证历史记录仍引用原实例。
4. 供应商登录中心，在「供应渠道」新增名称、类型、模型列表和上游密钥。编辑时留空密钥表示保留旧值。中心对上游密钥、下游管理令牌使用 AES-GCM 加密。目标端沿用现有渠道凭据存储，在撤回时清空上游密钥。
5. 本版供应表单提供 OpenAI、Anthropic、Gemini、DeepSeek、OpenRouter、New API 六种类型，OpenAI 兼容服务可选择 OpenAI 并填写其 Base URL。使用内置地址可留空。目标端部署自定义上游时，将受信任的完整 Base URL 加入 `SUPPLY_UPSTREAM_URLS`，多个地址用逗号分隔。需要插件登录或专用结构化凭据的渠道暂未纳入供应表单。
6. 兼容模式下，管理员选择「分配渠道」，指定目标实例和目标 UID。目标端校验用户存在且已启用，沿用其分组。中心显示期望目标、最近确认生效的目标和配置版本。管理员可以重试失败的同步；后台也会自动重试。对一个资源的并发编辑使用版本检查。
7. 「用量」支持按 UTC 自然日查询，每次最多 31 天，可按使用者、实例和模型筛选。数字表示消费日志条数、输入和输出 Token。重复采集替换相同分配、相同日期的快照。后台补采中断期间的窗口；窗口结束满一天后成功补采即归档。历史日期从中心已保存的窗口读取，当天可刷新到目标端。撤回后优先补采到结束次日；更晚结算的在途请求由独立后台任务按原分配寻找实际有消费的日期，再写入中心快照。用户查询历史时只读中心已保存的数据。缺失、采集失败或任一模型累计记录数、输入或输出 Token 下降时显示数据不完整，并保留已有快照和原采集时间；待完整数据恢复后再推进封存。目标端消费日志须启用，已在采集前清理的源日志需从源端备份恢复。
8. 「操作日志」展示最近 200 次资源变更和同步事件。归档保留分配与用量记录。撤回保留脱敏的远端渠道记录和永久回执，历史渠道 ID 不被复用。预览联调使用测试凭据和模拟上游。
